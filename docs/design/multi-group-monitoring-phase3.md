# 多策略组监控：第 3 阶段

前端已接入多组导航、任务独立编辑和共享容量提示。本阶段同时补齐按任务导出诊断包，并完成浏览器回归及真实 ARM64 设备上的隔离验收。

## 使用行为

- 持续监控页上方显示策略组列表，包括当前选择、模板、候选数量、启停状态及自动切换偏好。选择一个组后，概览、节点详情、事件时间线和监控设置均限定在该任务。
- “新增监控策略组”创建独立任务。已有任务的组在选择器中禁选，后端仍通过唯一约束处理并发创建冲突。所有可选组都已创建任务时，新增按钮禁用。
- 编辑器支持“保存后启用此任务”；编辑暂停任务时默认保持暂停，创建新任务默认启用。自动切换仍须单独显式开启。
- 各任务分别保留编辑草稿、观察窗口、当前页签、选中的序列和事件定位。切换策略组不丢草稿；离开整个监控页或刷新页面会清除未保存草稿。只记住最近选择的任务 ID，不把候选草稿写入浏览器存储。
- 轮询不会把新修订号套到旧草稿上。任务被其他窗口修改时，原草稿保留并提示冲突，服务端乐观锁拒绝过期保存。
- 切换任务会取消旧视图的请求；只轮询当前任务的详细历史，旧响应不能覆盖新任务。所有组的列表使用轻量运行摘要，不逐个计算长期排名，也不会等待正在进行的切换写入。
- 原有主题、中文/英文、键盘焦点和 320px 移动布局继续适用。

## 共享容量

“共享探测与存储”展示 Controller 最近一分钟请求使用量、预算上限，以及所有启用任务的名义预算和存储估算。编辑方案时，预览先移除该任务的旧配置，再计入当前草稿，其他任务保持已保存配置。

候选按任务成员计数：同一节点被两组监控，算作两条独立观测序列。若启用任务数为 `G`、候选总数为 `N`，当前估算为：

- 每日原始记录约 `720 × N + 2160 × G`，确认、复测与旧序列另计。
- 每日小时聚合约 `24 × N`。
- 多目标模板增加请求量，不按目标数量重复计算原始记录。
- 暂停任务不新增采样，但已保留的历史继续占空间。

名义请求超过共享上限或预计条数不足时会提示。候选编辑不会自动提高保留配额；“补足容量”仍只填写保留策略草稿，须显式保存才生效。保留策略由所有任务共享。

## 接口补充

- `GET /api/v1/monitor/tasks` 增加可选 `runtime` 摘要：`current`、`issue`、`suspended`、`unhealthy`、`unknown`、`observed_at`。若任务正忙于持锁操作，省略摘要，页面显示状态更新中。
- `POST /api/v1/monitor/tasks/{task_id}/diagnostics` 支持当前任务的 ZIP 或 JSON 下载封装。事件和采样均按任务归属查询；`include_legacy: true` 返回 400，因为无法归属的旧记录不能被标记成某个任务的证据。
- 未指定任务的旧接口继续保留第 1、2 阶段的兼容约束；新前端统一使用任务接口。

## 组件职责

| 组件或模块 | 职责 |
| --- | --- |
| `MonitoringPage` / `MonitoringHub` | 页面入口、任务选择、任务草稿与视图状态容器 |
| `MonitorTaskList` | 可访问的组切换与运行摘要 |
| `MonitorSharedCapacity` | Controller 范围的请求与存储容量 |
| `MonitorTaskView` / `useMonitorTaskView` | 单任务四个页签与明确任务身份的操作 |
| `useMonitorTasks` / `useMonitorOverview` | 列表和当前任务轮询、取消、离线恢复与过期响应防护 |
| `MonitorPlanEditor` / `useMonitorPlanEditor` | 候选草稿、修订锁、启停意图、共享容量预览与保存 |

## 验证结果与边界

2026-09-18 的本轮验证：

- Go vet、Go 全量测试、前端类型检查、96 项前端单元测试、92 项 Playwright 浏览器回归及嵌入资源一致性检查通过。
- 浏览器使用真实 Go 服务与隔离 `mihomo-mock`，验证创建多组、暂停创建、跨组草稿与修订冲突、单组启停/自动切换、历史隔离、诊断下载、迟到响应丢弃、中文桌面和英文 320px 页面。
- 截图审查发现并修复了移动端全局 `nav` 样式对任务列表的影响，并增加任务卡片宽度及内容溢出检查。
- 在 NanoPi R5S LTS / iStoreOS 24.10.8 / ARM64 上，以临时目录、独立 SQLite 和仅监听 loopback 的模拟 Controller 运行 5 组 × 30 个候选，持续约 145 秒：185 / 185 个预期基准时隙采集成功，所有候选覆盖率 100%，无共享存储暂停，观测到的 RSS 约 26 MiB。
- 临时实例重启后，5 个任务的配置与序列保持一致；其中 1 个任务的暂停状态保留，其余 4 个继续采样。临时进程、目录和转发已清理，原有生产进程与二进制保持不变。

设备验收使用 80ms 响应的模拟 Controller，不访问真实机场节点、不改动生产配置。这是短时功能与资源证据，不是实际网络、CPU 长期归因、90 天历史查询或 24 小时持续容量保证。当前环境未运行 Go race 检测。

可复用的受限验收工具是 `tools/check-multi-monitor.py`。它要求连接 `mihomo-mock` 且监控数据库为空，才会创建测试任务；可配置 2–10 组、每组 1–30 个候选以及 125–600 秒运行时间。`cmd/mihomo-mock` 增加 `-extra-groups` 与 `-extra-nodes` 以提供可控负载，默认行为保持不变。
