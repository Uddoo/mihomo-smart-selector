# 多策略组监控性能优化

本轮优化保持数据库 schema、120 秒基准周期、2 个后台 worker、360 次/分钟共享预算以及自动切换规则不变。无需为本轮性能改动执行数据迁移。

## 实现

1. **历史读取与统计**：小时归档以紧凑记录参与合并，复用小时解码缓冲；仅排序时隙编号，按序合并原始额外检查，再构造响应样本。原始基准优先覆盖同一时隙归档。统计对已排序、去重的基准输入直接扫描；其他调用保留稳定去重语义。P95 仍从实际成功延迟精确计算。
2. **按序列缓存**：每个任务按 `series_id + window` 缓存指标和最多 60 条样本，不缓存完整历史。基准提交递增该序列证据版本；额外检查只改变实时健康状态；保留清理使全部证据缓存失效。查询窗口首尾时隙变化、锚点变化、时钟回退和 120 秒 TTL 均触发重算。当前失败时隙的持续时间、观测跨度在命中缓存时仍随时间更新。概览发布前检查运行版本及证据版本，避免发布查询中途已变化的证据。
3. **前端轮询**：`GET /monitor/tasks?include=scheduler` 合并列表与预算摘要，原有无参数接口继续返回任务数组。保留策略独立读取，正常情况下每 60 秒校验，慢请求不会阻塞列表。设置/事件页暂停长期概览轮询，实时状态来自任务摘要；返回概览立即读取。节点详情依据所选序列证据、该节点事件和 30 秒时间校验更新。首次概览失败仍会退避重试。隐藏/离线时取消轮询，恢复后读取，保留草稿和旧响应隔离。
4. **列表、调度与扫描**：任务列表每次只读取任务 ID、revision、runtime，未变方案复用已解码副本，同时可识别其他数据库连接提交的新 revision。空闲任务在创建 goroutine/上下文前预检到期工作；暂停任务仍定期处理 Provider 事件收尾。扫描按名称索引合并结果，筛选条件使用 set；完整扫描快照替换时重建索引，结束时释放。

证据版本为进程内计数，不能作为持久化身份；前端仍结合任务、序列及 instance_id 识别数据。缓存不会用于延长实时健康状态的有效期；故障切换的历史读取保留即时计算路径。直接从其他进程修改历史数据不属于常规写入通道，序列缓存有时隙边界及 TTL 兜底。

组件职责保持不变：`MonitoringHub` 持有任务选择和草稿；`useMonitorTasks` 管理列表、预算及保留策略请求；`useMonitorOverview` 管理所选任务概览生命周期；`MonitorHistoryPanel` 管理所选节点时间线；子组件通过 props/emits 传递数据和保留策略读回结果。

## 基准结果（2026-09-20）

Windows/amd64、Intel i9-13900K、Go 1.27.0、`-cpu=1`，独立临时 SQLite，每候选 90 天小时归档、每小时 30 条基准记录，每场景两轮。完整 90 天为容量充足的合成夹具，不执行保留清理。未模拟 raw/hourly 重叠负载、HTTP 开销和真实 Controller 延迟。

| 候选/窗口 | 优化前未命中缓存 | 优化后未命中缓存 | 累计分配前 → 后 |
|---|---:|---:|---:|
| 12 / 24h | 22.38–22.59 ms | 3.50–3.51 ms | 6.22 → 3.09 MiB |
| 12 / 7d | 127.14–131.96 ms | 23.01–23.20 ms | 43.08 → 20.49 MiB |
| 30 / 24h | 52.36–59.04 ms | 8.17–8.20 ms | 15.55 → 7.71 MiB |
| 30 / 7d | 300.56–305.61 ms | 65.57–66.21 ms | 107.76 → 51.28 MiB |

30 候选/7 天的新增缓存场景：仅模拟健康版本更新约 0.177–0.180 ms；仅使一个节点历史缓存失效约 2.14–2.15 ms；完整概览缓存命中约 0.054–0.055 ms。这些场景固定时间、不启动真实采样；单行失效通过清除该行缓存模拟，不包含写入成本。

“未命中缓存”不代表磁盘冷启动；B/op 是累计分配量，不是峰值内存或 RSS；桌面机耗时不能直接作为路由器耗时。请求很快、页面可见且无额外操作时，监控基础轮询由约 48 次/分钟变为约 25 次/分钟，不包含页面外壳发现、诊断面板和详情请求。

复现（PowerShell，仓库根目录）：

```powershell
./.tools/go/bin/go.exe test ./internal/monitor -run '^$' -bench '^BenchmarkOverviewMatrix/nodes(12|30)/(24h|7d)/(cold|health_update|one_row_miss|cached)$' -benchmem -benchtime=500ms -count=2 -cpu=1
```

基准包含 `cold`、`health_update`、`one_row_miss` 和 `cached`，原有 `BenchmarkSevenDayOverviewFromNinetyDayArchive` 仍保留。

## 验证

- Go vet、全量 Go 测试通过。新增用例覆盖缓存与即时结果在时隙边界前后的等价、失败秒数推进、迟到基准、额外检查、缓存响应隔离、清理失效、实时故障状态、暂停任务到期工作、其他连接更新配置及扫描快照替换后的索引重建。
- 原有 raw/hourly 聚合、跨小时失败、缺测、暂停/重启、多任务隔离和故障切换测试保持通过。
- 前端 TypeScript 检查、生产构建、96 项单元测试通过；内嵌静态资源与独立生产构建一致（91 个文件）。
- 浏览器完整回归 96/96 通过，相关复测 20/20 通过。设置页断言验证任务列表持续刷新及草稿 revision 不被覆盖，覆盖首次失败恢复、多策略组、轮询减量、慢保留策略、独立节点更新、隐藏/离线恢复和 SSE 心跳；部署前独立 smoke test 也通过。
- 浏览器环境：项目隔离 Go 服务、临时 SQLite、模拟 Controller，Chromium；最后复测服务 `http://127.0.0.1:8209`，测试完成后自动关闭。桌面 1440×1000、移动 320×800，中文/英文，页面身份、内容、控制台、交互和横向溢出检查通过。Browser plugin not available，使用项目 Playwright 流程。
- 本机 `CGO_ENABLED=0`，未运行 race detector；未进行目标路由器部署或长期压力测试。现有 360 次/分钟预算仍然决定可支持的候选数与探测目标组合。
