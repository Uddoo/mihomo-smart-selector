**故障恢复时，让可靠性接近的低延迟节点优先。** `v0.4.0` 为持续监控新增按任务配置的成功率容差，避免很小的成功率差距压过明显的延迟优势。当前节点正常时仍保持原选择。

## 本次主要升级

- **容差内低延迟优先**：确认当前节点不可用后，先排除当前节点及不符合健康、新鲜度条件的候选。与合格替代节点中最高近 24 小时成功率相差不超过容差的节点，按 P95 升序、成功率降序、名称排序；其余节点按成功率降序、P95 升序、名称排列，保留为兜底。
- **每个任务独立配置**：在“持续监控 → 监控设置 → 编辑监控方案”设置“成功率容差（百分点）”。默认 **8 个百分点**，支持 **0–100** 的小数值；切换任务保留各自草稿，保存后刷新和重启仍保留。
- **可恢复原策略**：设为 **0** 恢复成功率优先、P95 打破并列；设为 **100** 时所有合格替代节点都按 P95 优先。
- **保留历史证据**：仅调整容差不会重建方案或观测序列，也不会清空历史样本。切换审计记录当次容差和选择规则，中英文界面同步说明。

容差是百分点之差，不是相对百分比。例如最高成功率 90%、容差 8 时，82% 及以上的合格候选进入优先组。所有候选都与同一个最高值比较，避免通过连续的小差距扩大优先组。

## 升级与兼容性

1. **已有自动切换任务会采用新的默认排序。** 旧方案缺少容差字段时使用 8；如需保留原顺序，升级后将其设为 0。已有监控和自动切换开关保留，原本关闭的自动切换不会自动开启。
2. **从 v0.3.x 升级不新增数据库结构迁移。** 升级前停止服务并备份旧程序、配置及完整数据目录。运行中的 SQLite 可能含 WAL，不能只复制单个数据库文件。从更早版本升级时仍需遵循相应的多任务迁移说明。
3. 创建、更新任务的 API 新增可选数值字段 `failover_tolerance_pp`。创建时省略采用默认值，更新时省略保留已有值；显式保存的 0 不会被默认值覆盖。
4. 重新加载网页获取新的内嵌资源，检查各任务容差、候选和近期采样。容差按任务保存，不会随实时数据自行变化。

## 验证与边界

回归覆盖固定参照排序、容差边界、并列与兜底顺序、快速候选复测失败、基准样本不被复测覆盖，以及旧方案默认值、零值持久化、非法输入、任务草稿隔离和历史身份保留。发布流水线执行 Go 测试/race、进程 smoke、前端与浏览器回归、安全检查和桌面包验证。

本次只改变**确认故障后的候选顺序**。候选健康、新鲜度、切换前复测、两分钟冷却、持久化审计、Controller 回读及未知结果停止重试仍生效；当前节点健康时不会因其他节点更快而主动切换。

默认容差是初始取舍，不是统计置信区间或长期最优值。样本较少、覆盖率不足或网络变化时，应结合实际数据调整。P95 来自成功基准探测，不证明带宽、登录、播放、地区解锁或长连接体验。

## English

`v0.4.0` adds per-task success-rate tolerance for failure-triggered monitoring
failover. Fresh, healthy alternatives within the configured margin of the highest
24-hour baseline success rate are tried by lowest P95, then highest success rate
and name. Other candidates remain as fallbacks in success-rate order. Every
candidate uses the same fixed reference.

The default is **8 percentage points**, configurable from **0–100**, including
decimals. Set **0** to restore success-rate-first ordering. Existing plans without
`failover_tolerance_pp` adopt the default; failover enablement is preserved.
Omitted fields in updates retain saved values, including zero. Editing the
tolerance preserves plan/observation identities and historical evidence. No
schema migration is added over v0.3.x. Review the setting after upgrading.

Failover remains opt-in and only runs after confirmed current-node failure.
Fresh health, pre-switch retests, cooldown, durable audit, Controller readback
and unknown-outcome protection remain in effect. Healthy current nodes are not
proactively replaced. The tolerance is a configurable tradeoff, not a confidence
interval or guarantee of future performance.

Download Windows AMD64/ARM64 or macOS Apple Silicon/Intel archives and verify
them with `SHA256SUMS.txt`. Windows ARM64 is cross-built only; Windows AMD64 and
both macOS targets have native CI package checks. Packages are unsigned and
macOS packages are not notarized. Linux/router builds use the documented
source-build path.
