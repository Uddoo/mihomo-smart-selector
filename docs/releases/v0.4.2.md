**独立测试 Claude API 的鉴权入口。** `v0.4.2` 新增 `claude-api` 模板，保留原有 Claude 静态资源探测，方便按实际使用路径选择服务。

## 本次更新

- 新增「Claude API 鉴权入口可达性」，无密钥 GET `https://api.anthropic.com/v1/models`，基础探测预期 HTTP 401。
- 可选严格验证要求 HTTP 401 且正文包含带双引号的 `"authentication_error"` 标识；403 标记为受限，429、其他状态或缺少标识均不通过。正文沿用子串检查，不是完整 JSON 结构验证。
- 新增 Claude API、Anthropic API、Claude Code 组名推荐；原有 Claude、Anthropic、Claude AI 推荐及保存的绑定不变。
- 补齐中英文说明、探测边界文档和九类响应回归测试，同步内嵌前端资源。

不发送密钥或模型生成请求。验证通过仅表示收到预期鉴权响应，不证明有效密钥、模型权限、生成调用、Claude Code 登录或地区资格可用，也不能代表第三方中转、Bedrock 或 Vertex AI 路径。

## 升级与兼容性

1. 更新程序并刷新网页后，在「测试服务」手动选择新模板；已有绑定和监控方案不会自动迁移。
2. 严格验证仍需配置并启用专用 Selector 和代理入口，默认可选。若配置 `probe_profile_overrides.claude-api.require_strict: true`，手动选节点必须有严格验证证据；持续监控仅做基础探测，因此自动切换会拒绝执行，需手动扫描验证。
3. 自定义模板若占用 `claude-api` ID，需先改名或迁移至 `probe_profile_overrides`。显式 `scanner.probe_profiles` 仍完整替换内置目录。
4. 从 v0.4.1 升级无数据库迁移。停止服务后备份程序、配置和完整数据目录，再替换程序；更早版本请同时遵循对应迁移说明。

## English

`v0.4.2` adds a separate `claude-api` profile while preserving the existing Claude static-resource profile and saved bindings. A credential-free GET to the Anthropic models endpoint expects HTTP 401. Optional strict validation also requires the quoted `authentication_error` token in the body. HTTP 403 is restricted; other statuses or missing content fail. This is a substring check, not full JSON validation, and does not prove model calls, Claude Code login or regional eligibility work.

Strict validation requires the existing dedicated selector and proxy configuration. Setting `require_strict: true` makes strict evidence mandatory for manual node selection; monitoring only performs basic probes, so automatic switching is refused for such profiles. Custom `claude-api` IDs must be renamed or migrated to overrides before upgrading. Explicit profile lists still replace the built-ins. No database migration is added over v0.4.1; stop the service and back up the program, configuration and complete data directory before replacement.

Verify downloads with `SHA256SUMS.txt`. Windows ARM64 is cross-built only; other desktop targets receive native CI package checks. Packages are unsigned and macOS packages are not notarized. Linux/router installations use source builds.
