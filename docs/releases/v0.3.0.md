**更轻的监控刷新，更低的历史计算开销。** `v0.3.0` 减少页面重复读取和无关数据传输，将监控明细改为按需加载，并降低历史指标计算的临时内存分配。现有完整 API、任务隔离、精确 P95 与切换安全规则保持兼容。

## 本次主要升级

- **Provider 名称摘要**：前端筛选使用 `GET /api/v1/providers?view=summary`，只读取名称。默认接口及 `view=full` 继续返回完整代理数据。
- **监控明细按需读取**：概览使用 `view=summary`，省略各节点的最近采样数组。进入节点详情时增加 `series_id`，只返回当前任务中所选节点的最近采样；历史趋势继续使用原有任务级接口。
- **按页面刷新数据**：扫描页读取完整准入数据，节点目录和连通性页各自读取所需数据；监控、设置与历史页初始加载后仅保留应用级健康轮询，各功能读取独立运行。返回扫描页必须重新完成数据发现与预检，旧响应不能重新启用操作。
- **紧凑历史计算**：从时隙、结果和精确延迟累加指标，只重建最后 60 条完整展示样本。原始记录优先于小时聚合，保留缺测、失败边界、任务缓存失效和精确 P95 语义。
- **代码结构整理**：前端按扫描、监控、连通性、目录、历史和设置归组；认证、发现、导航和扫描会话职责分开。后端在现有包内拆分路由、执行、状态和迁移文件。扫描会话仍由应用持有，切换页面不会中断正在进行的扫描。
- **维护流程完善**：新增固定版本格式检查，单元测试自动发现；同步当前架构、模块归属和贡献文档，更新 SQLite/Vue 等锁定依赖及内嵌资源。

## 性能与验证范围

同功能构建在 NanoPi R5S LTS / iStoreOS 上进行的一次 18 候选实机验收中：

| 响应 | 完整视图 | 摘要视图 | 减少 |
| --- | ---: | ---: | ---: |
| 34 个 Provider | 765,600 B | 894 B | 99.88% |
| 18 个候选的监控概览 | 381,323 B | 37,221 B | 90.24% |

响应体积随实际配置和历史内容变化，这些结果不构成任意部署的固定压缩比例。

在 Windows / i9-13900K / Go 1.27、单 CPU、合成归档数据的同口径基准中，30 候选、7 天窗口的冷概览从约 **64 ms 降至 43 ms**，每次累计分配从 **51.3 MiB 降至 15.7 MiB**。分别对照原始记录、混合记录与纯归档读取，累计分配约减少 46%、50% 和 70%。这是代码基准，累计分配不等于常驻内存，桌面耗时不代表路由器耗时。

本地 98 项前端单元测试、99 项浏览器回归、Go 全量测试和进程 smoke 通过。回归覆盖旧完整响应、摘要隔离、明细按需读取、跨任务迟到响应、返回扫描页的新鲜校验、缺测与历史指标等价，以及丢失切换响应后的 `request_id` 幂等重试。发布流水线另执行 Go race、CodeQL、依赖/密钥检查和各平台打包验证。

## 升级与兼容性

1. **从 v0.2.0 升级不新增数据库结构迁移。** 先停止服务，备份旧程序、配置、完整数据目录和外部密钥文件，再替换程序启动。运行中的 SQLite 可能包含 WAL，不能只复制单个数据库文件。
2. 重新加载网页以获取新的内嵌资源；Token 认证用户需要重新输入 Token。确认任务、候选、自动切换偏好和近期采样。
3. **从 v0.1.0 或更早版本升级，仍会执行多任务结构迁移。** 请同时遵循 [v0.2.0 升级说明](https://github.com/Uddoo/mihomo-smart-selector/blob/v0.3.0/docs/releases/v0.2.0.md#升级与兼容性)；回退到旧结构版本时必须恢复配套数据库备份。
4. 本次不执行历史孤儿记录清理，也不改变保留配额、探测并发或自动切换策略。

API 调用方可继续使用原有完整响应。摘要视图为可选参数；多个任务时，未指定任务的旧监控接口仍返回 HTTP 409。明细仅从已授权任务的当前节点行提供，其他任务的序列不会泄露到响应。任务及方案身份、切换审计和重试请求身份保持不变。

所有任务仍共享两个后台 worker 和最多 360 次探测请求/分钟。HTTPS 探测不证明登录、播放、地区解锁或长连接可靠性；故障自动切换继续要求显式开启并通过既有证据检查。

## English

`v0.3.0` reduces monitoring payloads, unnecessary discovery polling and temporary
allocations during historical calculations. Provider filters use a names-only
summary. Monitoring overviews omit recent sample arrays until a selected node's
details are requested. Default/full API responses remain compatible, and
task-scoped access, late-response protection and exact P95 semantics are preserved.

Discovery follows the active page. Returning to scan invalidates admission until
fresh discovery and preflight finish. The application continues to own scan
sessions across navigation. Historical metrics consume compact baseline evidence
and reconstruct only the recent display tail, preserving raw-over-aggregate
precedence, missing observations and failure boundaries.

Frontend features and application state now have explicit ownership; backend
responsibilities and migration code are separated within the existing packages.
Pinned formatting checks, automatic unit-test discovery and updated architecture
guides support maintenance. Locked dependencies and embedded assets are updated.

A single router acceptance run reduced a 34-provider response from 765,600 B to
894 B and an 18-candidate overview from 381,323 B to 37,221 B. Results vary with
configuration and history. A single-CPU synthetic desktop benchmark reduced the
30-candidate, seven-day cold overview from about 64 ms to 43 ms and cumulative
allocations from 51.3 MiB to 15.7 MiB. These are not router latency or resident
memory claims. Local validation passed 98 frontend unit tests and 99 browser
regressions, Go tests and the process smoke test; release CI adds race, security
analysis and platform package checks.

**Upgrading from v0.2.0 adds no schema migration.** Stop the service and back up the
executable, configuration, complete data directory and external secrets before
replacing the executable. Reload the UI afterward. Upgrades from v0.1.0 still
perform the task migration described in the v0.2.0 notes; downgrading across that
schema boundary requires the corresponding database backup. This release does
not clean historical orphan records or change retention/probe/failover limits.

Four desktop archives and `SHA256SUMS.txt` are provided. Windows AMD64 and both
macOS architectures receive native CI checks; Windows ARM64 is cross-built only.
Packages remain unsigned and macOS packages are not notarized. Linux/router
binaries continue to use the documented source-build path.
