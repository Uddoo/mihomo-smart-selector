**监控出口与 IP 情报功能版本。** `v0.5.0` 增加 ChatGPT 出口 IPv4/IPv6 与独立 IP 来源证据，支持网页管理凭据，并精简手机工作台与设置导航。

## 本次更新

- ChatGPT 持续监控通过专用探测路径观察出口地址和地区；成功 HTTPS 采样后按间隔检测，手动复测可刷新。读取页面不会触发探测。
- 并列展示 IPQualityScore、Scamalytics、ipapi.is、AbuseIPDB 的原始指标含义、时间、有效期和独立错误状态。未知字段不当作否定，零分不当作缺失；来源冲突保留可见。IP 情报不影响健康分、扫描排名或故障自动切换。
- IP 情报设置支持独立启用、密钥替换/撤销/清除、恢复服务端凭据，以及 Scamalytics 用户名与 API 节点。保存后后续查询生效，无需重启。
- 可选 loopback 出口 Controller 负责专用出口选择器；主 Controller 继续承担发现、HTTPS 探测、严格验证与业务切换。隔离核心由操作者配置管理。
- 设置分为外观、连接、扫描与验证、IP 情报、存储；桌面页签与手机选择器切换保留草稿和离页保护。
- 手机品牌、语言与主题控件合并；连通性初始页面减少无结果控件；扫描只显示一处准备引导。当前与候选并列比较评分 `/90`、P95、成功率和采样次数，保留验证与证据有效期。
- 凭据缓存及退避使用带随机客户端密钥的 HMAC-SHA-256 指纹，区分账户字段，避免可跨进程复用的无密钥摘要。

## 升级与兼容性

1. 配置和 API 为新增扩展，保留旧 IPQS 配置兼容；没有数据库结构迁移。已有绑定、监控任务和历史可保留。详见 [监控与 IP 情报说明](../monitoring.md)。
2. 升级前停止服务，备份程序、配置及完整数据目录，包括数据库、WAL 和私有凭据侧文件，再替换程序并启动。升级后刷新浏览器。
3. 网页凭据覆盖写入 `<storage.path>.ip-intelligence.json`，不回显已保存密钥，也不写入浏览器存储；该文件是私有文件而非加密存储。限制其权限并将其纳入备份。
4. 外部 IP 服务接收出口 IP、必要凭据和固定查询参数；缺少或禁用凭据不发起请求。各来源有独立缓存与退避，实际请求受共享监控预算限制。
5. 出口探测需要独立探测选择器和正确代理路由；应用核对并恢复选择器，无法确认恢复时丢弃证据。回读不能单独证明路由路径。可选 `egress_controller` 必须指向 loopback IP，不替代主业务 Controller。
6. 出口和 IP 情报缓存仅在内存中，重启后重新积累。源构建继续使用 Go 1.27.2 或更高版本。

## English

`v0.5.0` adds ChatGPT monitoring exit IPv4/IPv6 and independent IP intelligence from IPQualityScore, Scamalytics, ipapi.is and AbuseIPDB. Each source keeps its metric semantics, timestamps, expiry and errors; unknown fields, zero scores and conflicting evidence remain distinct. This evidence does not affect HTTPS health scores, scan ranking or automatic switching. Exit checks follow successful samples, with explicit manual refresh; GET snapshots do not launch probes.

Web settings support provider enable switches, credential replacement/undo/clear, restoration of server-side credential sources and Scamalytics account/node configuration. Saved changes apply to subsequent queries without restarting. Settings categories preserve drafts and navigation guards. The mobile shell and connectivity controls are more compact; scan initial guidance is consolidated and the candidate comparison shows score out of 90, P95, success rate and sample count.

Configuration and APIs are additive, legacy IPQS configuration remains supported, and there is no database schema migration. Stop the service and back up the program, configuration and complete data directory, including WAL and private credential sidecars, before replacing the binary. Refresh the browser afterward. Provider overrides are stored in `<storage.path>.ip-intelligence.json`, never returned by API reads or retained in browser storage; private-file persistence is not encryption at rest.

Providers receive the exit IP and required credentials. Disabled or unconfigured providers send no requests; caches, account backoff and shared request budgets bound traffic. Credential cache identities use HMAC-SHA-256 with a random per-client key. Exit and provider evidence is memory-only and accumulates again after restart. A dedicated probe selector and correct proxy routing are required. Optional `egress_controller` must use a loopback IP and only handles the exit probe path; the operator provisions the isolated core. Selector readback does not establish the actual traffic route.

Verify downloads with `SHA256SUMS.txt`. Windows ARM64 is cross-built only; Windows AMD64 and both macOS architectures receive native CI package checks. Packages are unsigned and macOS packages are not notarized. Linux/router installations continue to use source builds. Provider contract tests and mock browser checks do not establish live paid-provider behavior, production isolated-core routing or long-running reliability. Source builds require Go 1.27.2 or later.
