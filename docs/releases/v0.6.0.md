**扫描排名导入监控名单。** `v0.6.0` 支持一键将完成扫描的综合排名前 N 名替换到对应策略组的监控列表，保留原任务设置，并在服务端核对来源扫描与节点 Provider。

## 本次更新

- 扫描工作台排名表上方新增“扫描排名前 N 名”和“替换监控列表”。严格取本次扫描综合排名第 1 至 N 名，搜索、分页、排序视图和扫描后修改的表单策略组不影响取值或目标组。
- 默认取前 6 名，结果不足时取全部，最多 30 名。已有监控任务保留启停、自动切换、服务模板和成功率容差；候选上限不足时扩容，已有更大上限继续保留。
- 没有对应任务时，使用本次扫描的服务创建并启用监控，默认关闭自动切换。替换完整覆盖名单，不额外补入当前节点，也不跳过失败、仅初筛或过期的排名结果。
- 保存请求携带来源 `scan_id`，后端核对扫描所属 Controller、完成状态、原策略组、严格排名前缀及当前 Provider。校验失败或 revision 冲突时整体拒绝，不覆盖现有方案。
- 打开历史扫描期间锁定相关操作；替换的成功结果和错误显示在按钮旁。中英文界面与手机布局均有覆盖。
- 同步主线前端依赖更新，重新生成 Go 内嵌页面、gzip 资源和入口引用。

从 `v0.4.4` 升级还会获得监控出口与独立 IP 情报、网页凭据设置、可选 loopback 出口 Controller，以及设置和手机工作台改进，详见 [v0.5.0 功能说明](v0.5.0.md) 与 [完整更新日志](../../CHANGELOG.md)。

## 升级与使用

1. 停止服务并备份程序、配置与完整数据目录，包括数据库、WAL 和私有凭据侧文件，再替换程序、启动服务并刷新浏览器。本次监控名单导入没有数据库结构迁移。
2. 完成一次扫描，在排名表上方填写 N 并点击“替换监控列表”，随后进入“持续监控”检查对应策略组的名单。未完成、停止、失败或中断的扫描不能导入。
3. 导入只保存节点名单，扫描成绩不作为长期监控样本；监控继续自行采样，既有历史按原有规则保留。操作本身不切换业务策略组，已有自动切换策略继续按原设置运行。
4. 节点核对使用现有 Controller 目录缓存。节点不再属于该组或 Provider 已变化时，重新扫描后再导入。详见 [扫描结果说明](../scan-results.md)。

## 下载与校验

提供 Windows AMD64/ARM64 ZIP、macOS Apple Silicon/Intel tar.gz 和 `SHA256SUMS.txt`。Windows AMD64 与两种 macOS 架构由 CI 原生运行验证；Windows ARM64 为交叉构建。包未签名，macOS 未公证。Linux 和路由器部署继续按设备架构从源码构建。

标签流水线执行 Go/race、进程 smoke、前端与浏览器回归、安全扫描、桌面包运行验证和附件校验。功能构建另在 ARM64 路由器完成部署、健康、页面和升级时监控方案保留检查；该记录不等同于所有设备或长期负载验收。

## English

`v0.6.0` adds **Replace monitor list** to the scan workbench. After a scan completes,
choose N to replace the scan group's complete monitoring candidate list with
overall ranks 1 through N. Search, pagination, alternative sort views and later
form edits do not change the selected prefix or target group. The default is six
nodes, or all results when fewer are available, with a maximum of thirty.

Existing tasks retain their enabled state, automatic switching, service profile,
success-rate tolerance and larger candidate capacity. Capacity grows when needed.
Groups without a task receive an enabled task using the scan's profile, with
automatic switching disabled. The prefix is exact: it does not append the current
node or skip failed, unrefined or expired results.

Requests include the source `scan_id`. The server checks the stored scan's
Controller scope, completion state, target group, ranked prefix and current
Provider names before saving. Failed validation and revision conflicts leave the
existing plan unchanged. Historical-scan loading locks related workbench actions;
replacement results and errors appear beside the button. Chinese, English,
desktop and mobile layouts are covered.

Importing a list does not switch the business selector or copy scan scores into
monitoring history. Monitoring continues its own sampling and existing retention
rules. This feature adds no database schema migration. Stop the service and back
up the executable, configuration and complete data directory, including WAL and
private credential sidecars, before replacing the binary. Refresh the browser
after restarting. Candidate checks use the existing Controller discovery cache.

Upgrades from `v0.4.4` also include monitoring exit/IP intelligence, private web
credential settings, the optional loopback egress Controller and the settings and
mobile improvements documented in the `v0.5.0` feature notes. Mainline frontend
dependency updates and matching embedded/gzip assets are included.

Verify the four desktop archives with `SHA256SUMS.txt`. Windows AMD64 and both
macOS architectures receive native CI package checks; Windows ARM64 is
cross-built. Packages are unsigned and macOS packages are not notarized.
Linux/router installations use architecture-specific source builds. Tag CI runs
race tests, process smoke tests, frontend/browser regressions, security checks,
native package checks and checksum verification. Router evidence covers an ARM64
router feature build and does not establish every device or long-running load.
