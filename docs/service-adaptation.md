# 适配不同的 OpenClash / Mihomo 配置

应用通过 `mihomo.controller` 读取实际策略组，不依赖设备型号、订阅文件名或中文组名。
可以部署在路由器本机，也可以部署在能访问控制器的电脑或 NAS 上。
基础扫描通过目标 Mihomo API 发起；严格验证由应用经配置的专用代理路径发起。
跨机器部署时，`127.0.0.1` 指各自所在机器，不能直接照搬专用代理地址。

## 选择策略组和服务

1. 在“目标策略组”选择当前设备实际存在的 Selector。
2. 在“测试服务”选择一个模板；不必与策略组同名。
3. 检查预检显示的服务、探测范围和候选数量，再开始扫描。
4. 点击“保存绑定”让以后访问此应用的浏览器自动使用该绑定。

优先级：本次显式选择 → 数据库中的绑定 → 组名推荐 → 默认模板。
默认模板为 `internet-baseline`（基础 Internet 连通性），可用
`scanner.default_probe_profile` 修改。通用评分不能证明特定服务可用。
名称推荐沿用内置别名；例如“AI服务”推荐 ChatGPT，但可手动改选其他服务。

绑定保存在 `storage.path` 的 SQLite 数据库中，并按控制器地址隔离。
刷新页面、重启应用或换浏览器后仍保留；改用另一个控制器地址不会继承原地址的绑定。
地址不是设备硬件身份：若同一地址被另一台设备复用，应先检查或清除原绑定。
本轮仅支持单个控制器配置，不提供多设备切换界面或历史记录的多设备隔离。

页面空闲且可见时每 30 秒刷新一次，也可点击“刷新策略组”。扫描及切换期间暂停刷新。
组被删除、改名或变为非 Selector 时，原绑定保留并显示为失效，不会猜测新名称。
模板被删除时绑定也会失效；重新选择可用模板保存，或移除绑定后恢复推荐。
刷新失败时禁止开始新扫描，恢复连接后重新预检。
正在运行的扫描固定使用启动时的模板，切换前仍检查当前目标组和成员。

## 添加自定义模板

在现有配置的 `scanner` 下添加 `custom_probe_profiles`，然后重启应用：

```yaml
scanner:
  custom_probe_profiles:
    - id: my-api
      label: 我的 API 服务
      description: 测量自建 API 的 HTTPS 可达性，不证明业务操作成功。
      transport_scope: HTTP latency only
      probes:
        - name: health
          url: https://api.example.com/health
          expected_status: "200"
```

将示例地址换成自己的可达性探测地址。模板 ID 必须唯一，不得与内置模板重复。
自定义模板默认不向浏览器返回私有 URL；界面仍显示模板名称、说明和探测数量。
现有 `probe_profiles` 仍表示完整替换模板列表，`probe_profile_overrides` 仍用于覆盖
已有模板的探测参数；通常新增服务使用 `custom_probe_profiles` 更方便。
已有配置字段的意义保持不变。本轮不提供浏览器中的 URL 编辑器或 YAML 热重载。

没有严格验证专用路径时，基础扫描仍可工作。仅包含嵌套组的 Selector 仍会显示
不可扫描原因，本轮不展开嵌套策略组，也不修改 OpenClash 配置。

## 设置页的运行参数

“偏好设置”提供扫描并发、批次大小、候选上限、稳定模式采样次数、超时、最低切换成功率、
评分阈值、默认服务，以及出口地区验证和严格验证的开关、专用探测组与代理地址。
出口验证还可填写返回 `loc=JP` 等国家代码的 HTTPS 探测地址。

第一次读取 YAML 中的默认值。保存后，这些运行参数保存在同一个 SQLite 数据库，按
Controller 地址隔离，优先于 YAML，并立即应用到后续扫描；重启服务后会恢复。
YAML 仍管理服务模板、连接地址、密钥、监听与访问控制。修改 YAML 中的同名运行字段
不会覆盖已保存的 UI 设置；需要在页面修改并保存。“重新加载”会丢弃未保存编辑，
重新读取服务端当前值，不是恢复 YAML 默认值。

扫描运行时拒绝保存，其他浏览器修改过设置后会要求重新加载，避免覆盖别人的编辑。
保存不发起验证请求、不创建探测组、不修改 OpenClash 配置。启用时检查探测组必须
存在且为 Selector；代理入口是否指向该组仍需在 Mihomo 中配置正确。
验证会修改所指定的专用探测组，并在结束时尝试恢复原选择；不要使用业务组。
启用验证后禁止把探测组作为业务扫描目标，也禁止并行扫描共用探测组。

运行设置 API：`GET /api/v1/settings`、`PUT /api/v1/settings`。更新提交完整对象及
读取到的 `revision`，服务器对范围、地址格式、探测组和编辑版本进行校验。
API 不返回 Controller 密钥，也不提供修改连接或监听权限的入口。

## 服务 API

- `GET /api/v1/services`：模板摘要、绑定状态、组名建议和默认模板 ID。
- `PUT /api/v1/bindings`：`{"group":"任意策略组","profile_id":"youtube"}`。
  `profile_id` 为空字符串表示移除该组绑定，失效绑定也可移除。
- `POST /api/v1/scans/preflight` 和 `POST /api/v1/scans`：可传 `profile_id`。
  不传时按上述优先级解析；显式传入不存在的 ID 会报错，不会静默回退。

这些 API 沿用应用现有的认证和网络访问限制。自定义模板通过本地配置管理。

## 连接与密钥

`mihomo.controller` 设置目标控制器地址，`mihomo.secret_env` 指向密钥环境变量。
也可以设置 `mihomo.secret_file`，读取仅含一行密钥的私有文件；相对路径以应用
配置文件所在目录为基准。设置文件后优先使用文件，读取失败或空文件会阻止启动。
文件不应包含 YAML 的 `secret:` 字段，不得放入版本库；路由器上设置权限 0600。
应用不读取或更改任何固定 OpenClash 订阅 YAML。


## 两阶段扫描与服务准入

偏好设置中的“初筛后复测前 K 名”对应 `scanner.refine_top_k`（默认 10）。
稳定模式先对全部候选的每个地址采样一次，再对前 K 名及筛选范围内的当前节点
补足 `max(2, samples)` 次采样。仅初筛的节点保留在列表中，但需要复测后才能选择。
页面分别显示初筛/复测请求数、成功数/总数、采样时间及与当前节点的同轮比较。

“结果有效期”对应 `scanner.result_max_age_seconds`（默认 600 秒）。有效期从节点
最近的延迟采样时间计算，服务端在切换时重新检查。过期后点击“复测此节点”，
等待新扫描结束并再次确认；复测本身不会切换业务节点。旧持久化设置缺少新增字段时，
自动继承 YAML 默认值；旧稳定扫描缺少复测证据时需要重新测试。

可在服务模板或 `probe_profile_overrides` 中启用额外条件，例如：

```yaml
scanner:
  probe_profile_overrides:
    chatgpt:
      require_strict: true
      require_region: true
      expected_regions: [JP, US]
```

两个条件默认关闭。`require_strict` 要求模板具有严格探测规则，并在切换时确实
验证通过；`require_region` 要求模板声明预期地区，并取得匹配的出口验证结果。
相关验证未启用、超出预算或验证失败时，服务端拒绝选择并返回原因；不会自动放宽条件。
严格验证现在按排名执行预算内的节点，超出预算的节点明确标记为未验证。

`POST /api/v1/scans/{id}/retest` 接收 `{"node":"节点名称"}`，返回新的扫描（202）。
创建扫描也支持 `nodes` 精确名称筛选；仍受业务组直接成员关系和候选数上限限制。
目录查询允许最多两秒缓存，扫描、保存绑定和切换前成员校验始终读取当前 Controller。
